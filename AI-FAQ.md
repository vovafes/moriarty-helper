# 🤖 AI-FAQ: Moriarty-Helper

Это технический документ для ИИ-ассистента, помогающего в поддержке бота Moriarty-Helper.

## 📌 Общий обзор
Данный бот является упрощенной версией системы управления семьей в Discord, сфокусированной на базовых функциях: сборы, тикеты, экономика, АФК/Инактив и мониторинг ВЗП.

## 📂 Структура проекта
- `main.py`: точка входа; код бота разнесён по `legacy/` (по файлу на раздел), модули панели — `panel_modules/`, новые модули с настройками — `modules/`, ядро панели — `core/` + `dashboard/`.
- `laws_module.py`: Модуль ассистента: поиск (FTS5) по законам + вики, вызов LLM (Ollama → запасной Groq, оба через aiohttp), мероприятия.
- `update_laws.py`: Скрипт для обновления базы законов (таблица `laws`).
- `update_wiki.py`: Скрипт для обновления вики wiki.gta5rp.com (таблица `wiki` в той же `laws.sqlite`, копии в `wiki_raw/`). Отдельная таблица, чтобы очистка устаревших тем в `update_laws.py` не стирала вики.
- `llm_keys.py`: Пул ключей Ollama (`ollama_keys.json`, в .gitignore). Ключ с лимитом (429) или ошибкой (401/402/403) уходит на «отдых» и берётся следующий; ключи из `.env` (`OLLAMA_API_KEY`, `OLLAMA_API_KEYS` через запятую) тоже участвуют. В веб-панель (модуль «ИИ-ассистент», `panel_modules/assistant.py`) ключи отдаются только масками `••••abcd`; поля с `"secret": True` не попадают в журнал аудита.
- `events_feed.py`: Живое чтение раздела форума «Мероприятия на сервере» (кэш 5 мин). Дата/время берутся из названия темы, статус — из префикса.
- `laws_raw/`: Папка с markdown-файлами правил сервера.
- `data.json`, `obshak.json`, `points.json`, `chips.json`, `roulette.json`: JSON-хранилища.

## ⚙️ Основные системы
1. **Сборы:** Создание списков на мероприятия с кнопками записи и тредами.
2. **Тикеты:** Базовая система подачи заявок и их рассмотрения.
3. **Экономика:** Система баллов (алмазы 💎) и фишек (🎰), включая простой магазин.
3. **АФК/Инактив:** Отслеживание отсутствующих участников.
4. **ВЗП Мониторинг:** Интеграция с API `vzp-gta5rp.com` для отслеживания войн семей и уведомления участников.
5. **Юридический помощник:** Поиск по базе законов и правил сервера Murrieta.

## 🛠 Технические особенности
- **Библиотека:** discord.py.
- **Синхронизация:** Данные сохраняются в JSON через `save_data()`.
- **Специфика:** В отличие от `multitasking`, здесь нет полноценной интерактивной панели настроек (конфигурация через отдельные команды).

## ⚠️ Важные правила
- **Консистентность данных:** При изменении любого состояния БД (например, `points_db` или `warns_db`) обязательно вызывать `save_data()`.
- **Брендинг:** Футер всех эмбедов — `MORIARTY`.

## 🖥 Панель и модули (ветка dashboard)
- Панель (`dashboard/`) живёт в event loop бота; модули грузятся в `setup_hook` ДО старта веб-сервера (иначе их маршруты не добавятся).
- Новый модуль = файл в `modules/` с `modules.register(Module(...))` (схема полей → форма в панели), cog и `setup(bot)`; добавить в `MODULE_EXTENSIONS` в `main.py`. Таблицы — `register_table`, действия с формами — `Action`.
- Старое состояние (`legacy/state.py`) подключается к панели адаптерами `loader/saver` в `panel_modules/`. Словари общие по ссылке: никогда не переприсваивать их (`x = {}`), только менять на месте.
- Тесты не должны писать в реальные `data.json`/`pvp_config.json` (они пишутся относительно cwd) — тесты, импортирующие legacy, делают `os.chdir(tmpdir)` до вызова `save_data`.
- Живой бот может работать из этой же папки: при проверке не запускайте второй экземпляр с боевым токеном.
